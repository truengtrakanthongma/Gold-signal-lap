# Gold Signal Lab — ระบบวิเคราะห์ทองคำเรียลไทม์พร้อมเหตุผลประกอบ

เครื่องมือบนเบราว์เซอร์สำหรับเทรดเดอร์ทองคำ: กราฟเรียลไทม์ + วิเคราะห์สัญญาณซื้อ/ขาย
พร้อม **เหตุผลภาษาไทยว่าทำไม** + **จุดเข้า/จุดตัดขาดทุน/เป้าทำกำไร** + **ความน่าจะเป็นที่วัดจากสถิติจริง**
+ **ระบบแจ้งเตือน** (เสียง / แจ้งเตือนหน้าจอ / อ่านออกเสียง / Discord webhook)

ไม่ต้องติดตั้งอะไร ไม่ต้องมี API key ไม่มีไลบรารีภายนอก — เป็น HTML + JavaScript ล้วน

- **แจ้งเตือนเข้ามือถือ** ผ่านแอป TradingView — ปิดคอมได้

น้ำหนักปัจจัยและค่าตั้งต้นตรงกับเวอร์ชันเว็บทุกตัว มีเทสต์คอยตรวจไม่ให้เพี้ยนจากกัน

## ⚠️ กราฟไม่ตรงกับของโบรกเกอร์? อ่านตรงนี้

**ค่าเริ่มต้นไม่ใช่ราคาทองคำสปอต** แอปดึง **PAXG/USDT** ซึ่งเป็นโทเคนที่หนุนด้วยทองคำจริง
1 เหรียญ = 1 ทรอยออนซ์ ราคาวิ่งเกาะทองคำสปอต (XAU/USD) แต่**ไม่เท่ากันเป๊ะ**
ต่างกันได้ประมาณ 0.1–1% ตามอุปสงค์อุปทานของโทเคนเอง โดยเฉพาะช่วงตลาดทองจริงปิด

ถ้าเอาไปเทียบกับกราฟทองของโบรกเกอร์แล้วตัวเลขไม่ตรง **นั่นไม่ใช่กราฟผิด แต่เป็นคนละสินทรัพย์**

แอปบอกไว้ตรงใต้ราคาแล้วว่ากำลังดูอะไรอยู่ พร้อมจำนวนแท่งและช่วงวันที่โหลดมา

**วิธีใช้ราคาทองสปอตจริง:** สมัครฟรีที่ twelvedata.com → คัดลอก API key
→ ตั้งค่า → วางในช่อง API key → เปลี่ยนแหล่งข้อมูลเป็น "Twelve Data XAU/USD"

> 🔑 **API key เก็บใน localStorage ของเบราว์เซอร์คุณเท่านั้น ไม่เคยถูกเขียนลงโค้ดหรือส่งขึ้น repo**
> อย่าใส่คีย์ลงในไฟล์โค้ดเด็ดขาด เพราะ repo และเว็บเป็นสาธารณะ ใครก็เอาไปใช้จนโควตาหมดได้

## ข่าวโลกที่กระทบราคาทอง

แท็บ **บริบทตลาด & ข่าว** ดึงหัวข้อข่าวเรียลไทม์แล้วบอกว่าแต่ละข่าว
ตามทฤษฎีควรดันทองไปทางไหน พร้อมกลไกว่าทำไม

### สิ่งที่ต้องเข้าใจก่อนใช้

หน้าเว็บนี้เป็นไฟล์นิ่ง ๆ ไม่มีเซิร์ฟเวอร์หลังบ้าน **จึงไม่มีปัญญาประดิษฐ์อ่านข่าวให้**
สิ่งที่ทำได้จริงคือจับคำสำคัญ แล้วเทียบกับฐานความรู้ 12 ตัวขับราคาทอง

| ทำได้ | ทำไม่ได้ |
|---|---|
| บอกว่าข่าวแตะเรื่องที่มีผลกับทอง | อ่านบริบท / แยกประชด |
| บอกทิศตามทฤษฎี พร้อมกลไก | รู้ว่าตลาดรับข่าวไปแล้วหรือยัง |
| กรองข่าวคนละเรื่องที่มีคำว่า gold | วัดขนาดผลกระทบจริง |

หน้าจอเขียนข้อจำกัดนี้ไว้ให้ผู้ใช้เห็น ไม่ใช่ซ่อนในโค้ด

### ฐานความรู้ 12 ตัวขับ

ตัวอย่างที่ให้น้ำหนักสูงสุด: **ผลตอบแทนพันธบัตรที่แท้จริง** (น้ำหนัก 10, ยีลด์ขึ้น = ทองลง)
เพราะทองไม่มีดอกเบี้ย ถ้าพันธบัตรให้ผลตอบแทนจริงสูงขึ้น การถือทองก็เสียโอกาสมากขึ้น
ทุกตัวขับมีคำอธิบายกลไกเป็นภาษาไทย และมีเทสต์บังคับว่าต้องมี — ผู้ใช้ต้องเข้าใจว่าทำไม ไม่ใช่เห็นแค่ลูกศร

### จุดที่พลาดง่ายและวิธีกัน

**ทิศทางกลับหัวได้ทั้งดุ้น** ถ้าอ่านกริยาไม่ครบรูปผัน เวอร์ชันแรกมีแต่ `falls`
จึงอ่าน *"Treasury yields fall"* (พหูพจน์ กริยาไม่เติม s) เป็น **กดทอง** ทั้งที่ยีลด์ร่วงต้อง **หนุนทอง**
— กลับหัวกับความจริงคนละขั้ว เจอตอนทดสอบบนเบราว์เซอร์ ไม่ใช่ตอนเขียน
ตอนนี้ใช้ regex ที่รู้ขอบเขตคำ และมีเทสต์คุมรูปผันไว้ 5 แบบ

**คำที่มีทิศอยู่ในตัวเองห้ามถูกกลับ** — *"Fed signals rate cut as inflation cools"*
ต้องกลับแค่ "เงินเฟ้อ" ไม่ใช่กลับ "ลดดอกเบี้ย" ให้กลายเป็นขึ้นดอกเบี้ย
ตัวขับจึงมีธง `invertible` แยกคำกลาง ๆ (ดอลลาร์ ยีลด์ เงินเฟ้อ) ออกจากคำที่มีทิศแล้ว (rate cut, hawkish)
และคำกลับทิศต้องอยู่ใกล้คำสำคัญภายใน 40 ตัวอักษร ไม่ใช่โผล่ที่ไหนก็ได้ในประโยค

**ข่าวคนละเรื่องที่มีคำว่า gold** — Gold medal, Goldman Sachs, Golden State ถูกกรองออกทั้งหมด
และ "central bank" ที่ไม่พูดถึงทองเลย ไม่ถูกนับเป็นแรงซื้อทอง

### แหล่งข่าว — ลองสามเจ้าตามลำดับ

บริการข่าวฟรีที่ยอมให้เว็บเรียกตรง ๆ (CORS) มีน้อยมาก และเจ้าที่ใช้ได้ก็ต่างกันไปตามเครือข่ายของผู้ใช้
ระบบจึงลองเรียงตามลำดับจนกว่าจะได้:

| ลำดับ | แหล่ง | จุดเด่น |
|---|---|---|
| 1 | **GDELT** | ครอบคลุมข่าวทั่วโลก ตรงประเด็นที่สุด |
| 2 | **Hacker News (Algolia)** | เปิด CORS แน่นอน แทบไม่เคยล่ม — ตัวสำรองที่เชื่อถือได้ |
| 3 | **Reddit** (r/economics + r/investing + r/Gold) | หัวข้อข่าวการเงินที่คนโพสต์จริง |

NewsAPI.org แผนฟรี**บล็อกการเรียกจากเบราว์เซอร์** จึงใช้กับหน้าเว็บนิ่ง ๆ ไม่ได้เลย

**ถ้าทุกเจ้าล้ม หน้าจอจะแสดงตารางว่าลองเจ้าไหนไปบ้างและติดตรงไหน** —
ไม่ใช่แค่ "ดึงข่าวไม่ได้" ซึ่งแก้อะไรไม่ได้

ดึงทุก 10 นาที — ข่าวไม่ได้ออกถี่กว่านั้น และการถล่มคำขอใส่บริการฟรีคือวิธีที่เร็วที่สุดที่จะโดนบล็อก

## แจ้งเตือนเข้า Discord

หน้าเว็บต้องเปิดค้างไว้ถึงจะเตือนได้ แต่ Discord เด้งเข้ามือถือแม้ปิดจอ
และเก็บประวัติสัญญาณย้อนหลังให้เองด้วย

ใส่ URL ของ webhook ในแท็บ **แจ้งเตือน** แล้วกด **ส่งข้อความทดสอบ**
สัญญาณจริงจะส่งเป็นการ์ดที่มี ราคาเข้า · จุดตัดขาดทุน · เป้าหมาย · ขนาดไม้ · ได้:เสีย · อัตราชนะในอดีต

### บั๊กที่แก้: ช่องแจ้งเตือนที่ล้มเงียบ ๆ

โค้ดเดิมกลืน error ทั้งหมด พร้อมคอมเมนต์ว่า *"ปลายทางบล็อก CORS ก็ไม่ต้องรบกวนผู้ใช้"*
ซึ่งเป็นการตัดสินใจที่ผิด: **ช่องแจ้งเตือนที่ล้มเงียบ ๆ แย่กว่าไม่มีเลย**
เพราะผู้ใช้จะนั่งรอสัญญาณที่ไม่มีวันมา โดยเชื่อว่าระบบกำลังเฝ้าให้อยู่

ตอนนี้รายงานผลการส่งครั้งล่าสุดเสมอ — สำเร็จเมื่อไร ใช้เวลาเท่าไร หรือล้มเพราะอะไร
(429 ส่งถี่เกิน · 404 webhook ถูกลบ · CORS เครือข่ายบล็อก)

### URL ของ webhook คือความลับ

ใครได้ไปก็โพสต์เข้าห้องคุณได้ จึงเก็บใน localStorage ของเบราว์เซอร์เท่านั้น ไม่เขียนลงไฟล์
และระบบ**ตรวจรูปแบบ URL ก่อนยิงทุกครั้ง** — ถ้าวางผิดที่ไป ข้อมูลการเทรดจะไม่ถูกส่งไปยัง
เซิร์ฟเวอร์แปลกหน้า เทสต์คุมไว้ 11 เคส รวมถึงโดเมนที่ปลอมเส้นทางมา (`evil.com/api/webhooks/...`)
และโดเมนที่ลงท้ายคล้ายกัน (`mydiscord.com`)

### ปฏิทินข่าว: ใส่เฉพาะที่คำนวณได้แน่นอน

| ข่าว | สถานะ |
|---|---|
| **NFP** | คำนวณเป๊ะ (ศุกร์แรกของเดือน 19:30 น. เวลาไทย) |
| **CPI** | บอกเป็นช่วงโดยประมาณ (ราววันที่ 10-15) วันจริงไม่ตายตัว |

ถ้าเดาวัน FOMC เองแล้วผิด ผู้ใช้จะไม่มีทางรู้ว่าผิด ซึ่งอันตรายกว่าไม่บอกเลย

## เปิดครั้งแรก: โหมดง่าย + ทัวร์พาชม

เครื่องมือเทรดมักมีปุ่มเต็มหน้าจอจนไม่รู้จะเริ่มตรงไหน แอปนี้จึงเปิดมาใน **โหมดง่าย**
เหลือแค่ 4 อย่าง: ราคา · กราฟ · กล่อง "ตอนนี้ควรทำอะไร" · คำอธิบายกราฟ
(ช่องกรอกและปุ่มลดจาก 48 เหลือ 19)

ครั้งแรกที่เปิดจะมี **ทัวร์พาชม 7 ขั้น** ไฮไลต์ทีละจุดพร้อมอธิบายว่าแต่ละส่วนคืออะไร
กดปุ่ม **❓ สอนใช้** เรียกดูซ้ำได้ตลอด

กล่อง "ตอนนี้ควรทำอะไร" พูดภาษาชาวบ้านล้วน ไม่มีศัพท์เทคนิค เช่น

> 🟢 **ตอนนี้เข้าซื้อได้** — เพราะปัจจัยหลัก ๆ ชี้ไปทางเดียวกัน และสัญญาณแบบนี้ในอดีตทำกำไรได้ 58 จาก 100 ครั้ง
> **ทำต่อยังไง:** เปิดโปรแกรมเทรด ตั้งคำสั่งรอที่ราคา 3,412.50 ตั้งจุดตัดขาดทุนที่ 3,398.20
> แล้วตั้งขายทำกำไรที่ 3,426.80 — ตั้งเสร็จแล้วปิดจอไปทำอย่างอื่นได้เลย ไม่ต้องเฝ้า

กด **🔧 โหมดเต็ม** เมื่อพร้อมดูผลทดสอบย้อนหลัง ตัวชี้วัดทั้งหมด และการตั้งค่า

**ศัพท์เทคนิคทุกคำมีคำแปลไทยกำกับ** เช่น "ความแรงของแนวโน้ม (ADX)",
"แรงส่งของราคา (MACD)", "ราคาต้นทุนเฉลี่ยของวัน (VWAP)" — ตั้งใจให้เห็นคู่กัน
เพราะผู้เรียนจะไปเจอศัพท์อังกฤษในโปรแกรมเทรดอื่นอยู่ดี

## อัตราชนะต่ำ = แย่จริงหรือ

**ไม่เสมอไป** สิ่งที่ตัดสินว่ากำไรหรือขาดทุนคือ *ค่าคาดหวังต่อไม้* ไม่ใช่อัตราชนะ

| ได้ : เสีย | ต้องชนะเกินกี่ % ถึงเท่าทุน |
|---|---|
| 1 : 1 | 50% |
| 1.5 : 1 | 40% |
| 2 : 1 | **34%** |
| 3 : 1 | **25%** |

ระบบแสดงจุดคุ้มทุนคู่กับอัตราชนะจริงในการ์ดแผนเทรด — ถ้าชนะ 40% ที่อัตราส่วน 2:1
นั่นคือ**ระบบที่ทำกำไร** ไม่ใช่ระบบที่แย่

### ถ้าค่าคาดหวังยังติดลบจริง ๆ ทำอะไรได้บ้าง

1. **โหลดข้อมูลให้มากขึ้น** (ตั้งค่า → โหลดข้อมูลย้อนหลัง) — 1,000 แท่งบนกรอบ 15 นาที
   คือข้อมูลแค่ 10 วัน ได้ไม่กี่สิบไม้ ซึ่งน้อยเกินกว่าจะบอกได้ว่ามีความได้เปรียบจริงหรือบังเอิญ
   ระบบดึงได้ถึง 10,000 แท่ง โดยไล่ขอเป็นชุด
2. **ขึ้นเกณฑ์คะแนน** — ไม้น้อยลงแต่คัดมาแล้ว ดูตาราง "ความน่าจะเป็นตามระดับคะแนน"
   ว่าช่วงคะแนนไหนให้ค่าคาดหวังเป็นบวก
3. **เปลี่ยนกรอบเวลา** — บางกรอบเวลาสัญญาณสะอาดกว่ามาก ลอง 1h/4h เทียบกับ 15m
4. **ดูตาราง "ปัจจัยไหนทำนายได้จริง"** — ตัวไหนส่วนต่างติดลบ ให้ลดน้ำหนักลงในแท็บตั้งค่า
5. **ยอมรับว่าบางช่วงตลาดไม่มีความได้เปรียบ** — ระบบที่ซื่อสัตย์ต้องบอกได้ว่า "ช่วงนี้อย่าเทรด"
   ซึ่งมีค่ากว่าระบบที่บอกให้เข้าตลอดเวลา

### ตัวกรองที่ระบบใช้สถิติของตัวเอง

เปิดไว้เป็นค่าเริ่มต้น: ถ้าช่วงเวลาไหน (ตามเวลาไทย) เคยขาดทุนซ้ำ ๆ ในอดีตอย่างน้อย 8 ไม้
ระบบจะ**ระงับสัญญาณในช่วงนั้น**พร้อมบอกเหตุผลและตัวเลข — ไม่ใช่แค่แสดงสถิติให้ดูเฉย ๆ

## คำบรรยายกราฟสด (สำหรับการเรียนรู้)

ใต้กราฟมีแผง **"กราฟตอนนี้กำลังบอกอะไร"** ที่เขียนอธิบายสถานการณ์เป็นภาษาไทยแบบอ่านรู้เรื่อง
สร้างจากตัวเลขจริงบนกราฟ ณ วินาทีนั้น และอัปเดตตัวเองตลอดเวลา แบ่งเป็น 7 หัวข้อ:

1. **ราคาตอนนี้** — ราคา การเปลี่ยนแปลง และแท่งเทียนล่าสุดกำลังเล่าอะไร
2. **ใครคุมเกมอยู่** — แนวโน้มจากเส้นค่าเฉลี่ยและโครงสร้างจุดสูง-จุดต่ำ
3. **แรงซื้อ-แรงขาย** — RSI / MACD / ปริมาณ พร้อมเตือนเมื่อโมเมนตัมสวนแนวโน้มหลัก
4. **ราคาอยู่ตรงไหนของสนาม** — ระยะห่างจากแนวรับ-แนวต้าน แปลเป็น "กี่แท่งกว่าจะถึง"
5. **ความผันผวนและจังหวะเวลา** — ATR แปลเป็นภาษาคน และช่วงตลาดตอนนี้
6. **กรอบเวลาใหญ่เห็นตรงกันไหม**
7. **สรุป — ควรทำอะไรตอนนี้**

ทุกครั้งที่ใช้ศัพท์เทคนิค จะอธิบายความหมายกำกับในประโยคเดียวกัน เช่น
*"RSI = 61 (ตัวเลข 0-100 ที่วัดว่าแรงซื้อหรือแรงขายชนะกันแค่ไหนในช่วง 14 แท่งล่าสุด) —
ฝั่งซื้อกำลังนำ และยังไม่ร้อนเกิน ถือว่าเป็นโซนสุขภาพดีของขาขึ้น"*

## วิธีเข้าไม้ — บอกทีละขั้นจนกดตามได้

การ์ดแผนเทรดไม่ได้บอกแค่ราคาเดียว แต่บอกครบว่าต้องทำอะไรบ้าง:

**ขั้นที่ 1 — ตั้งคำสั่งที่ราคาไหน** มี 3 กรณีชัดเจน
- 🟢 **ดีที่สุด** — ตั้ง Limit รอย่อกลับมาที่แนวรับ/เส้นค่าเฉลี่ย (ได้ระยะดีกว่า)
- ⚪ **หรือ** — เข้าเลยที่ราคาตลาด (ได้เข้าแน่นอน แต่ระยะแย่กว่า X ดอลลาร์)
- 🔴 **ห้ามเข้า** — ถ้าราคาเลยจุดหนึ่งไปแล้ว

จุด "ห้ามเข้า" ไม่ได้กำหนดมั่ว ๆ แต่คำนวณจากสมการ:

```
(เป้า − ราคาเข้า) ÷ (ราคาเข้า − ตัดขาดทุน) = อัตราส่วนขั้นต่ำ
แก้หา "ราคาเข้า" ได้ = (เป้า + ขั้นต่ำ × ตัดขาดทุน) ÷ (1 + ขั้นต่ำ)
```

เลยราคานี้ไป ได้:เสีย จะต่ำกว่า 1.2 : 1 ซึ่งไม่คุ้มเสี่ยง — สูตรเดียวใช้ได้ทั้งฝั่งซื้อและขาย

**ขั้นที่ 2 — ตัวเลขที่ต้องใส่** Stop Loss / Take Profit / ขนาด Lot เป็นตาราง คัดลอกไปกรอกได้ตรง ๆ

**ขั้นที่ 3 — กดยืนยันแล้วปิดจอ** ไม่ต้องเฝ้า

**แผนนี้ยกเลิกเมื่อไร** — 3 เงื่อนไขที่ชัดเจน พร้อมราคาที่แน่นอน

## เข้าไม่ทันจังหวะเร็ว ๆ ทำอย่างไร

ราคาและกราฟอัปเดตทุกวินาทีผ่าน WebSocket แต่ปัญหาจริงคือ *สัญญาณมาตอนไม่ได้เฝ้าจอ*
ระบบแก้ด้วย 3 อย่าง:

**1. โหมดแจ้งเตือน 3 แบบ** (เลือกได้ในแท็บแจ้งเตือน)

| โหมด | เตือนเมื่อไร | เหมาะกับ |
|---|---|---|
| **เตือนล่วงหน้า + ยืนยัน** (ค่าเริ่มต้น) | เตือน "เตรียมตัว" ทันทีที่คะแนนเข้าใกล้เกณฑ์ 80% แล้วยืนยันอีกครั้งตอนแท่งปิด | คนส่วนใหญ่ |
| **ทันที** | ทันทีที่คะแนนถึงเกณฑ์ ไม่รอแท่งปิด | สแกลป์ รับสัญญาณกลับไปกลับมาได้ |
| **เฉพาะแท่งปิด** | รอแท่งปิดอย่างเดียว | สวิงเทรด เน้นความนิ่ง |

**2. นับถอยหลังแท่งปิด** — บนแถบกราฟบอกว่าอีกกี่นาทีแท่งจะปิด จะได้รู้ว่ามีเวลาเตรียมตัวเท่าไร

**3. ตั้งคำสั่งรอแทนการไล่ราคา** — แผนเทรดจะบอกราคาเข้าที่ชัดเจน ให้ตั้ง limit order
กับ stop loss ทิ้งไว้ในโปรแกรมเทรด ถ้าราคามาถึงระบบโบรกเกอร์จะเข้าให้เอง
**ไม่ต้องนั่งเฝ้าจอ และไม่ต้องกดแข่งกับความเร็วตลาด** — นี่คือวิธีที่ตรงจุดที่สุด

## ระบบตัดสินใจอย่างไร

### 1. ให้หลายปัจจัย "โหวต" แทนที่จะเชื่อตัวชี้วัดเดียว

แต่ละปัจจัยคืนค่า **ทิศทาง** (+1 ซื้อ / −1 ขาย) × **ความแรง** (0–1) × **น้ำหนัก** พร้อม **เหตุผลภาษาไทย**

| ปัจจัย | น้ำหนัก | ดูอะไร |
|---|---|---|
| EMA Alignment | 16 | ราคา/EMA20/EMA50/EMA200 เรียงตัวกันไหม |
| ADX / DI | 12 | เทรนด์แรงพอให้เทรดตามหรือยัง |
| MACD | 12 | โมเมนตัมกำลังเร่งหรือแผ่ว + จุดตัด |
| Market Structure | 12 | ยอดและฐานยกสูงขึ้น (HH/HL) หรือกดต่ำลง |
| RSI | 10 | ตีความต่างกันตามสภาพตลาด (ดูข้อ 2) |
| Price Action | 10 | Engulfing, Pin bar, Star, Inside bar breakout |
| แนวรับ-แนวต้าน | 10 | ระยะห่างจากแนวจริง (นับจาก swing ที่เคยกลับตัว) และการเบรก |
| RSI Divergence | 10 | ราคาทำจุดใหม่แต่ RSI ไม่ตาม = แรงเริ่มหมด |
| Bollinger | 8 | บีบตัวแล้วเบรก / ราคาสุดขอบแบนด์ |
| Volume | 8 | มีเงินจริงหนุนหรือแค่แกว่งลอย ๆ |
| VWAP | 6 | คนที่ถืออยู่กำไรหรือขาดทุน |
| Stochastic | 6 | จุดตัดในโซนสูง/ต่ำ |

**คะแนน = Σ(น้ำหนัก × ความแรง × ทิศทาง) ÷ 120 × 100** → ช่วง −100 ถึง +100
คะแนนของแต่ละปัจจัยถูกจำกัดไม่ให้เกินน้ำหนักของตัวเอง เพื่อกันการนับซ้ำ

### 2. เปลี่ยนวิธีตีความตามสภาพตลาด (Regime switching)

- **ADX ≥ 22 = ตลาดมีเทรนด์** → RSI 55–78 คือ "แข็งแรง ไปต่อ" ไม่ใช่ "ซื้อมากเกินไป"
- **ADX < 22 = ตลาดออกข้าง** → RSI < 32 คือ "ถูกกดเกินไป เด้งได้" และขอบ Bollinger กลายเป็นแนวรับ/ต้าน

นี่คือสาเหตุที่ระบบง่าย ๆ แบบ "RSI > 70 = ขาย" ขาดทุนในตลาดเทรนด์

### 3. ตรวจสอบข้ามกรอบเวลา

คะแนนสุดท้าย = กรอบหลัก 55% + กรอบใหญ่ที่ 1 30% + กรอบใหญ่ที่ 2 15%
ถ้ากรอบเล็ก**สวนทาง**กรอบใหญ่ คะแนนถูกตัดลง 40%

### 4. ตัวกรองความปลอดภัย (ระงับสัญญาณแม้คะแนนถึงเกณฑ์)

- อยู่ในช่วง ±30 นาทีรอบข่าวแรง (NFP คำนวณอัตโนมัติ, ข่าวอื่นกรอกเองได้)
- ความผันผวนต่ำเกิน (ไม่คุ้มสเปรด) หรือสูงเกิน (เสี่ยงกว่าที่คำนวณ)
- อยู่นอกช่วงตลาดหลัก (ตัวเลือกเสริม)

### 5. แปลงเป็นแผนเทรดที่ลงมือได้จริง

- **Stop Loss** = ATR × 1.5 หรือเลยจุด swing ล่าสุด (เลือกอันที่กว้างกว่า แต่ไม่เกิน 3× ATR)
  เพราะ SL ต้องกว้างพอที่ "การแกว่งปกติ" จะไม่เขี่ยออกก่อน
- **เป้าหมาย** 1R / 2R / 3R และถ้ามีแนวต้านขวางอยู่ก่อนถึงเป้า ระบบจะเตือนหรือย้ายเป้ามาก่อนแนวนั้น
- **ขนาดไม้** = เงินที่ยอมเสี่ยง ÷ (ระยะ SL × 100 ออนซ์ต่อ lot) — คำนวณจากระยะ SL จริง ไม่ใช่เดา

## ความน่าจะเป็นมาจากไหน

**ไม่ใช่ตัวเลขที่ตั้งขึ้นเอง** — มาจากการเดินกฎชุดเดียวกันย้อนหลังทุกแท่งในข้อมูลที่โหลดมา
(ฟังก์ชัน `scoreAt()` ตัวเดียวกับที่ใช้กับสัญญาณสด) แล้วนับว่า *แตะเป้า 1R ก่อนโดน SL กี่ครั้ง*

การจำลองใช้กติกาแบบอนุรักษ์นิยม:

- เข้าที่ **ราคาเปิดของแท่งถัดไป** (ราคาที่เข้าได้จริง) ไม่ใช่ราคาปิดที่ยังไม่รู้ตอนตัดสินใจ
- บวกสเปรดตอนเข้า และสลิปเพจตอนโดน SL
- ถ้าแท่งเดียวแตะทั้ง SL และ TP → **นับเป็นแพ้เสมอ** (ข้อมูลแท่งเทียนบอกลำดับไม่ได้)
- ไม่ซ้อนไม้ — ไม้ใหม่เริ่มได้หลังไม้เก่าปิดแล้วเท่านั้น
- แผนบริหารไม้ = ปิดครึ่งที่ 1R เลื่อน SL มาที่ทุน ที่เหลือไปต่อที่ 2R (ตรงกับที่แนะนำบนหน้าจอ)

ผลลัพธ์แยกเป็นตาราง **ช่วงคะแนน** (คะแนนสูงควรชนะบ่อยกว่า) และ **ช่วงเวลาไทย**
(บอกว่าควรเทรดชั่วโมงไหน) พร้อม **ช่วงความเชื่อมั่น 95% แบบ Wilson** เพราะอัตราชนะจาก 20 ไม้
กับจาก 200 ไม้ เชื่อถือได้ไม่เท่ากัน

### ตรวจสอบแบบแบ่งข้อมูล (walk-forward) — ตัวเลขที่ควรเชื่อจริง ๆ

Backtest ธรรมดามีจุดอ่อนใหญ่: เราเลือกเกณฑ์จากข้อมูลชุดไหน แล้ววัดผลบนชุดนั้น
ตัวเลขจะสวยเสมอ เพราะเป็นการ "ตอบข้อสอบที่เห็นเฉลยแล้ว"

ระบบจึงแบ่งข้อมูลเป็นสองท่อนโดยอัตโนมัติ:

| ท่อน | ใช้ทำอะไร |
|---|---|
| **ช่วงเรียนรู้** (60% แรก) | กวาดหาว่าเกณฑ์คะแนนเท่าไรให้ค่าคาดหวังดีที่สุด |
| **ช่วงสอบจริง** (40% หลัง) | เอาเกณฑ์นั้นไปวัดผล โดยระบบไม่เคยเห็นข้อมูลส่วนนี้มาก่อน |

**ตัวเลข % บนการ์ดสัญญาณดึงมาจากช่วงสอบจริงเสมอ** (ถ้ามีไม้ตั้งแต่ 15 ไม้ขึ้นไป)
และหน้าผลทดสอบจะโชว์ทั้งสองค่าคู่กันพร้อมส่วนต่าง — ถ้าผลตกเกิน 15%
แปลว่าระบบจำข้อมูลเก่าได้ มากกว่าเข้าใจตลาดจริง

ถ้าช่วงสอบจริงขาดทุน ระบบจะขึ้นคำเตือนสีแดงบนการ์ดสัญญาณตรง ๆ ว่า
**"ยังไม่ควรเทรดตาม"** ไม่ปล่อยให้ตัวเลขสวย ๆ หลอกผู้ใช้

### จุดตัดขาดทุนและเป้าหมาย คำนวณจากสถิติ ไม่ใช่ตั้งเอง

เดิมจุดตัดขาดทุนตั้งไว้ที่ 1.5 เท่าของ ATR และเป้าเป็น 1R/2R/3R ตายตัว ซึ่งเป็นการเดา
ตอนนี้ระบบ**กวาดหาค่าที่ดีที่สุดจากข้อมูลจริง**:

- ลองความกว้างจุดตัดขาดทุน 5 ค่า × เกณฑ์คะแนน 7 ค่า × ระยะเป้าหมาย 8 ค่า
- แต่ละไม้บันทึกว่า "ราคาวิ่งไปได้ไกลสุดกี่เท่าของความเสี่ยง **ก่อน**จะโดนตัดขาดทุน"
  ทำให้ประเมินเป้าหมายทุกระยะได้จากการจำลองรอบเดียว
- **หาจากช่วงเรียนรู้เท่านั้น แล้วพิสูจน์กับช่วงสอบจริง** — ไม่งั้นก็แค่จูนให้พอดีกับอดีต

**เลือกอย่างมีวิจารณญาณ ไม่ใช่เอาค่าสูงสุด:** ถ้าหยิบจุดที่ค่าคาดหวังสูงสุดตรง ๆ
มักได้จุดโดด ๆ ที่ดีเพราะบังเอิญ พอเปลี่ยนค่านิดเดียวก็พัง ระบบจึงให้คะแนนแต่ละจุด
ด้วยค่าเฉลี่ยของตัวมันเองกับจุดข้างเคียง — ชนะคือจุดที่อยู่บน "ที่ราบสูง" ไม่ใช่ยอดแหลม

**สถิติที่ใช้ตอบว่าทำไม** (กางดูได้ในการ์ดแผนเทรด):

| สถิติ | ตอบคำถามว่า |
|---|---|
| ไม้ที่ชนะเคยติดลบลึกสุดแค่ไหน | จุดตัดขาดทุนกว้างพอไหม หรือกว้างเกินจำเป็น |
| ราคาวิ่งไปได้ไกลแค่ไหน (ครึ่งหนึ่ง/75%/90%) | เป้าที่ตั้งไว้สมจริงไหม |
| อัตราถึงเป้าแต่ละระยะ ทั้งสองช่วง | ทำไมถึงเลือกระยะนี้ |

ถ้าไม้ที่ชนะ 95% ไม่เคยติดลบเกิน 0.7 เท่าของระยะ SL ระบบจะบอกตรง ๆ ว่า
**SL กว้างเกินจำเป็น** — แคบลงได้ เสี่ยงเงินเท่าเดิมแต่ได้ขนาดไม้ใหญ่ขึ้น

### ปัจจัยไหนทำนายได้จริง

ตารางเทียบให้เห็นว่าแต่ละปัจจัย เวลามัน**เห็นด้วย**กับทิศทางที่เข้าไม้ อัตราชนะเป็นเท่าไร
เทียบกับตอนมัน**ค้าน** — ส่วนต่างคือความได้เปรียบที่วัดได้จริงของปัจจัยนั้น
ถ้าติดลบแปลว่าปัจจัยนั้นให้สัญญาณสวนความจริงในข้อมูลชุดนี้ ควรลดน้ำหนักลง

นี่คือวิธีตรวจว่าน้ำหนักที่ตั้งไว้ในตารางข้างบน สมเหตุสมผลกับตลาดจริงหรือเป็นแค่การเดา

### ระบบศึกษาตลาดเอง แล้วปรับกลยุทธ์ตามที่เรียนรู้

ค่าตั้งต้นทุกตัว — คะแนนขั้นต่ำ 35, จุดตัดขาดทุน 1.5 เท่า ATR, เป้า 2 เท่าของความเสี่ยง —
เป็นค่ากลาง ๆ ที่ตั้งไว้ล่วงหน้าโดยไม่เคยดูตลาดที่คุณโหลดมา แต่ตลาดไม่ได้มีคาแรกเตอร์เดียว
ช่วงหนึ่งเป็นเทรนด์ยาว อีกช่วงเป็นกรอบแคบ ความผันผวนก็ไม่เท่ากัน

ในแท็บ **ผลทดสอบย้อนหลัง** ปุ่ม **"ให้ระบบศึกษาตลาดแล้วปรับกลยุทธ์เอง"** จึงจำลอง
การจูนใหม่เป็นระยะแบบที่คนเทรดจริงทำ โดยแต่ละครั้งเห็นได้แค่อดีต:

```
ช่วงที่ 1  [───เรียนรู้───][สอบ]
ช่วงที่ 2  [──────เรียนรู้──────][สอบ]
ช่วงที่ 3  [─────────เรียนรู้─────────][สอบ]
ช่วงที่ 4  [────────────เรียนรู้────────────][สอบ]
```

ทุกช่วง "สอบ" คือข้อมูลที่ตอนจูนไม่เคยเห็น เอาผลมาต่อกันจึงได้ผลจริงของ *ระบบที่ปรับตัวเอง*
แล้วเทียบกับ **ค่าคงที่บนช่วงเวลาเดียวกันเป๊ะ** — จึงตอบได้ว่าการปรับตัวเองช่วยจริงหรือไม่

#### เว้นระยะกันข้อมูลรั่ว (embargo)

ไม้ที่เข้าใกล้เส้นแบ่งจะไปปิด *หลัง* เส้นแบ่ง ผลของมันจึงขึ้นกับแท่งในช่วงสอบ
ถ้าเอามาจูนก็เท่ากับแอบเห็นอนาคตไปแล้วบางส่วน ระบบจึงหยุดรับไม้ใหม่ก่อนถึงเส้นแบ่ง
เท่ากับระยะถือสูงสุด ไม้ทุกไม้ที่ใช้จูนจึงปิดก่อนเส้นแบ่งแน่นอน

มีเทสต์พิสูจน์: จูนจากข้อมูลทั้งชุด ต้องได้ค่าเดียวกันเป๊ะกับจูนจากข้อมูลที่ตัดอนาคตทิ้ง

#### ผลที่วัดได้ — และเหตุผลที่ต้องมีมากกว่าหนึ่งตัวควบคุม

การอ้างว่า "ปรับตัวเองแล้วดีขึ้น" พิสูจน์ยาก เพราะการจูนย่อมทำให้ตัวเลขในอดีตสวยขึ้นเสมอ
จึงทดสอบกับข้อมูลสามแบบ อย่างละ 26 ชุด:

| ข้อมูล | ปรับตัวเอง | ค่าคงที่ | ส่วนต่าง | ดีขึ้น |
|---|---|---|---|---|
| **สุ่มล้วน** คาแรกเตอร์เดียวตลอด | −0.013 R/ไม้ | 0.002 R/ไม้ | −0.015 (t = −0.81) | 12/26 |
| **เปลี่ยน regime เป็นขั้น** ทุก ~500 แท่ง | 1.175 R/ไม้ | 1.072 R/ไม้ | +0.103 (t = 5.12) | 23/26 |
| **เสมือนตลาดจริง** ผันผวนเกาะกลุ่ม + หางอ้วน + เทรนด์ค่อยเปลี่ยน | 0.199 R/ไม้ | 0.226 R/ไม้ | **−0.027 (t = −1.64)** | **10/26** |

**แถวที่สองเคยเป็นตัวเลขที่เอามาอวด — และมันหลอก**

t = 5.12 ดูน่าเชื่อมาก แต่มันมาจากเครื่องปั่นข้อมูลที่เปลี่ยนคาแรกเตอร์**แบบเป็นขั้นชัดเจน**
ทุก 500 แท่ง ซึ่งเป็นสนามที่เข้าข้างการจูนใหม่เต็ม ๆ เพราะมี "ก้อน" ให้จับชัด ๆ
ตลาดจริงไม่เปลี่ยนแบบนั้น และไม่ประกาศล่วงหน้าว่ากำลังจะเปลี่ยน

แถวที่สามคือข้อมูลที่ใกล้ตลาดจริงกว่า — ความผันผวนเกาะกลุ่มแบบ GARCH,
หางอ้วน (วันเหวี่ยงแรงเกิดบ่อยกว่าการแจกแจงปกติ), และเทรนด์ที่ค่อย ๆ เปลี่ยนอย่างต่อเนื่อง
**ประโยชน์หายไปหมด และติดลบเล็กน้อยด้วยซ้ำ**

เหตุผลตรงไปตรงมา: เมื่อตลาดเปลี่ยนแบบค่อยเป็นค่อยไป ค่าที่ดีที่สุดแทบไม่เปลี่ยนตาม
การจูนใหม่ทุกช่วงจึงไม่ได้เพิ่มความรู้ เพิ่มแต่ความแปรปรวน

**สรุปอย่างซื่อสัตย์:** การปรับตัวเองช่วยเฉพาะตอนที่ตลาดเปลี่ยนคาแรกเตอร์เป็นก้อน ๆ ชัดเจน
ทองคำจริงเป็นแบบไหน **ยังไม่มีใครในโปรเจกต์นี้วัดได้** เพราะเครื่องที่พัฒนาต่อเน็ตไปดึงราคาจริงไม่ได้
ปุ่มในหน้าเว็บจึงวัดให้เองบนข้อมูลของคุณ และ**ยอมให้ใช้ค่าใหม่เฉพาะเมื่อวัดแล้วดีกว่าจริงเท่านั้น —
ถ้าผลออกมาเสมอ ค่าตั้งต้นชนะ** เพราะของใหม่ต้องพิสูจน์ตัวเอง ไม่ใช่ของเดิม

#### สิ่งที่เรียนรู้ "นิ่ง" แค่ไหน — สำคัญพอ ๆ กับกำไร

ถ้าทุกช่วงจูนได้ค่าใกล้เคียงกัน แปลว่าระบบจับคาแรกเตอร์ของตลาดนี้ได้จริง
ถ้าค่ากระโดดไปมาทุกช่วง แปลว่ากำลังไล่ตามเสียงรบกวน — หน้าจอบอกตรง ๆ ว่าเป็นแบบไหน
และถ้า "แกว่งมาก" ปุ่มใช้ค่าที่เรียนรู้จะไม่ขึ้นมา

ระบบยังตรวจ **การเสื่อมของผล** ด้วย: เทียบช่วงสอบท้าย ๆ กับช่วงต้น ๆ
ถ้าตกลงชัดเจนแปลว่าตลาดเปลี่ยนไปจากที่เรียนมา และจะเตือนให้ลดขนาดไม้หรือหยุด

### เรียนรู้น้ำหนักปัจจัยจากผลจริง — และปฏิเสธถ้าพิสูจน์ไม่ผ่าน

น้ำหนักทั้ง 12 ปัจจัย (เส้นค่าเฉลี่ย 16, ความแรงแนวโน้ม 12, …) ตั้งจากตำราและประสบการณ์
ไม่ใช่จากข้อมูลของคุณ ในแท็บ **ผลทดสอบย้อนหลัง** จึงมีปุ่ม
**"เรียนรู้แล้วสอบน้ำหนักชุดใหม่"** ที่ทำสามขั้นตามลำดับ:

1. **เรียนรู้** — เก็บไม้จากช่วงแรกของข้อมูล (ใช้เกณฑ์คะแนนต่ำกว่าปกติเพื่อให้ได้ตัวอย่างมากพอ)
   แล้วฟิต logistic regression หา "ปัจจัยไหนสัมพันธ์กับไม้ที่ถึงเป้าจริง"
2. **สอบ** — เอาน้ำหนักที่ได้ไปเดินระบบบนช่วงหลัง ที่ตอนเรียนรู้ไม่เคยเห็น
   เทียบกับน้ำหนักเดิมแบบตัวต่อตัว
3. **ตัดสิน** — ผ่านก็ต่อเมื่อดีขึ้นเกิน 0.05 R ต่อไม้ **และ** สุ่มทดสอบซ้ำ 2,000 รอบ
   แล้วชุดใหม่ยังชนะ ≥ 90% ของรอบ ถ้าไม่ผ่าน ปุ่ม "ใช้น้ำหนักชุดใหม่" จะไม่ขึ้นมาเลย

#### สามอย่างที่ทำให้มันไม่ใช่แค่การจูนให้เข้ากับอดีต

| ปัญหา | อาการถ้าไม่แก้ | วิธีแก้ในโค้ด |
|---|---|---|
| ไม่ปรับสเกลตัวแปร | ปัจจัยที่นาน ๆ ติดที ถูก L2 บีบจนหาย ทั้งที่อาจแม่น | ทำ z-score ก่อนฟิต ทุกปัจจัยวัดด้วยไม้บรรทัดเดียวกัน |
| ตัดค่าติดลบแล้วปรับสเกลใหม่ | ปัจจัยไม่กี่ตัวดูดน้ำหนักไปทั้งหมด | วัดความนิ่งด้วย bootstrap — เครื่องหมายพลิกไปมา = ไม่ใช่หลักฐาน |
| ข้อมูลน้อยเทียบกับจำนวนปัจจัย | สัมประสิทธิ์แกว่งตามความบังเอิญ | **ผสม**กับน้ำหนักเดิม ไม่ใช่แทนที่ สัดส่วน = n/(n+200) |

ผลที่วัดได้จริงจากการทดลอง 40 ชุดข้อมูล (แบ่ง 60/40 เรียนรู้/สอบ):

| วิธี | ผลต่างค่าคาดหวังนอกช่วงเรียนรู้ | ปัจจัยที่หายไป |
|---|---|---|
| ฟิตดิบแล้วใช้เลย | **−0.055 R/ไม้** (t = −1.99) — แย่ลงจริง | 5.8 จาก 12 |
| หลังแก้ทั้งสามข้อ | −0.005 R/ไม้ (t = −0.43) — เท่าเดิม | 0 |

อ่านตารางนี้ให้ตรง: การแก้ทำให้ของที่เคย**ทำร้ายระบบ** กลายเป็นของที่**ไม่ทำร้าย**
แต่ยัง**ไม่ได้พิสูจน์ว่าช่วย** — บนข้อมูลจำลองไม่มีโครงสร้างให้เรียนรู้ ผลจึงควรเป็นศูนย์อยู่แล้ว
และด่านตรวจก็ทำหน้าที่ถูก: จากข้อมูลสุ่ม 20 ชุด **ไม่อนุมัติสักชุดเดียว**

จะรู้ว่าช่วยจริงไหม ต้องกดปุ่มบนข้อมูลทองคำจริงของคุณเอง แล้วดูว่าด่านตรวจยอมให้ผ่านหรือไม่

### การป้องกันการมองอนาคต (look-ahead bias)

ข้อผิดพลาดที่ทำให้ backtest ส่วนใหญ่ "สวยเกินจริง" คือการเผลอใช้ข้อมูลอนาคต โค้ดนี้ป้องกันไว้ 3 จุด:

1. **Swing pivot** ที่แท่ง j จะถือว่ารู้ได้ก็ต่อเมื่อผ่านไปอีก k แท่ง (`confirmedAt = j + k`)
2. **การจับกลุ่มแนวรับ/ต้าน** ทำตามลำดับเวลาที่ยืนยัน ไม่ใช่เรียงตามราคาทั้งชุด
   (ไม่งั้น pivot ในอนาคตจะไปเปลี่ยนการแบ่งกลุ่มของอดีต)
3. **พารามิเตอร์ความกว้างโซน** ใช้ ATR จาก 200 แท่งแรกเท่านั้น

และมีเทสต์พิสูจน์: คะแนนที่แท่ง i ต้องเท่ากันเป๊ะ ไม่ว่าจะป้อนข้อมูลทั้งชุดหรือตัดข้อมูลหลังแท่ง i ทิ้ง

## "ชนะ" แล้วต้องได้กำไรคุ้มที่เสี่ยงไป

ผู้ใช้ตั้งข้อสังเกตว่า ระบบชนะได้จริงแต่กำไรต่อการชนะน้อยมาก
และการชนะที่ได้กำไรน้อยกว่าที่เสี่ยงไปนั้นไม่มีความหมาย — ถูกต้อง และมีสองสาเหตุคนละเรื่องกัน

### สาเหตุที่ตรวจแล้วพบว่า "ยังไม่เกิด"

ตัวหาเป้าหมายที่ดีที่สุดเคยมีตัวเลือก **0.75R** อยู่ในรายการ คือเสี่ยง 1 เพื่อได้ 0.75
ซึ่งต้องชนะเกิน 57% ถึงจะเสมอตัว วัดแล้วพบว่า**ระบบไม่เคยเลือกมันเลยสักครั้งใน 36 ชุดข้อมูล**
(เลือก 2R เกือบตลอด) จึงเป็นความเสี่ยงที่ยังไม่เกิด ไม่ใช่สาเหตุ — แต่ปิดทิ้งไปแล้วเพราะไม่มีเหตุผลจะเก็บไว้
ตอนนี้มี `minTargetR` เป็นพื้นขั้นต่ำ (ค่าตั้งต้น 1.0) บังคับทั้งตัวหาค่า ตัวปรับกลยุทธ์เอง และแผนเทรดสด

### สาเหตุจริง: การปิดครึ่งไม้ที่ 1R

ระบบเดิมปิดครึ่งไม้เมื่อถึง 1R แล้วเลื่อน SL มาที่ทุน ผลคือ:

| ผลลัพธ์ | สัดส่วน | ได้กี่ R |
|---|---|---|
| ถึงเป้า 2R | 31.9% | +1.50R |
| **ถึง 1R แล้วถูกเขี่ยที่ทุน** | **18.5%** | **+0.50R** |
| โดน SL | 48.6% | −1.02R |

**เกือบ 1 ใน 5 ของไม้ทั้งหมด "ชนะ" แล้วได้กำไรครึ่งเดียวของที่เสี่ยงไป** ทั้งที่ตอนแพ้เสียเต็ม
อัตราชนะบนหน้าจอจึงดูดีกว่าความจริง

มีปัญหาซ้อนอีกชั้น: ตัวหาเป้าหมาย (`evaluateTarget`) คำนวณแบบ**ถือเต็มไม้**มาตลอด
ขณะที่ backtest หลักปิดครึ่ง ตัวเลขสองที่จึงคนละฐาน เทียบกันไม่ได้มาตั้งแต่ต้น

### วัดผลจริง 16 ชุดข้อมูล

| วิธีบริหารไม้ | ชนะ ≥1R | กำไรเฉลี่ยตอนชนะ | ไม้กำไรจิ๊บจ๊อย | ค่าคาดหวัง/ไม้ | ขาดทุนสะสมสูงสุด |
|---|---|---|---|---|---|
| ปิดครึ่งที่ 1R (เดิม) | 32.0% | 1.12R | 27.6% | **0.083** | **12.3R** |
| **ถือเต็มไม้ถึงเป้า** (ใหม่) | **43.0%** | **1.94R** | **11.0%** | 0.046 | 30.5R |
| ถือเต็มไม้ + เลื่อน SL กันทุน | 25.0% | 1.96R | — | 0.008 | 20.2R |

**อ่านตารางนี้ให้ตรง — ไม่มีวิธีไหนชนะขาด**

การถือเต็มไม้ให้สิ่งที่ผู้ใช้ต้องการจริง (กำไรเฉลี่ยตอนชนะ 1.12R → 1.94R, ไม้จิ๊บจ๊อย 27.6% → 11.0%)
แต่**ขาดทุนสะสมสูงสุดเพิ่มจาก 12.3R เป็น 30.5R** — ถ้าเสี่ยง 1% ต่อไม้ คือทุนหาย 12% เทียบกับ 30%
ส่วนค่าคาดหวังต่างกัน 0.037R/ไม้ ซึ่ง **t = −1.25 คือแยกไม่ออกจากความบังเอิญ**
พูดง่าย ๆ: ได้เงินพอ ๆ กัน แต่ทางเดินคนละแบบ

การเลื่อน SL มากันทุนแย่ชัดเจน (t = −10.03, แพ้ 16/16 ชุด) — มันเขี่ยเราออกจากไม้ที่สุดท้ายจะชนะ

ค่าตั้งต้นตอนนี้คือ **ถือเต็มไม้** และเปลี่ยนได้ในแท็บผลทดสอบย้อนหลัง

### ตัวเลขบนหน้าจอที่เพิ่มเข้ามา

- **ชนะจริง (กำไร ≥ 1R)** — ชนะที่ลบล้างการแพ้หนึ่งไม้ได้จริง
- **กำไรเฉลี่ยตอนชนะ** — ต่ำกว่า 1R เมื่อไร แปลว่าชนะไปก็ไม่คุ้ม
- **ไม้ที่กำไรน้อยกว่าทุน** — สัดส่วนไม้ที่ "ชนะ" แบบไม่มีความหมาย

## ตัวจับ "ราคาค้าง" — กลไกความปลอดภัยที่สำคัญที่สุด

WebSocket ค้างแบบ **"เปิดอยู่แต่ไม่ส่งอะไรมา"** เกิดบ่อยมากบนมือถือ — จอดับ,
สลับ WiFi เป็นเน็ตมือถือ, เข้าลิฟต์ ในกรณีนี้ `onclose` ไม่ยิง ระบบเดิมจึงไม่รู้ตัวเลย
แล้วโชว์ราคาเก่าค้างไว้พร้อมสัญญาณ "เข้าซื้อ" เหมือนทุกอย่างปกติ

**นั่นอันตรายกว่าการไม่มีสัญญาณเลย** เพราะผู้ใช้จะเข้าไม้ตามราคาที่ไม่มีอยู่จริงแล้ว

ระบบจึงบันทึกเวลาที่ได้ข้อมูลล่าสุดทุกครั้ง แล้วมีนาฬิกาเฝ้าดูทุก 5 วินาที ถ้าเงียบเกินเกณฑ์:

1. **ขึ้นแถบแดงบนสุดของหน้า** บอกว่าค้างมากี่วินาที/นาที
2. **ระงับสัญญาณทันที** — ใส่เป็นเหตุผลใน `blocks` ซึ่งเป็นตัวเดียวกับที่ตัวกรองข่าว/ความผันผวนใช้
   ดังนั้นแผนเทรดหายไปจริง ไม่ใช่แค่ขึ้นคำเตือนไว้ข้าง ๆ
3. **พยายามต่อใหม่เอง** ทุก 20 วินาที เพราะสาเหตุที่พบบ่อยที่สุดแก้ได้ด้วยการต่อใหม่เท่านั้น
4. **เช็กทันทีที่กลับมาดูหน้าจอ** (`visibilitychange`) และตอนเน็ตกลับมา (`online`)
   ซึ่งเป็นสองจังหวะที่ข้อมูลค้างบ่อยที่สุด ไม่ต้องรอรอบถัดไป

เกณฑ์ต่างกันตามผู้ให้บริการ — WebSocket ควรมีข้อมูลตลอด เงียบเกิน **90 วินาที** = ผิดปกติ
ส่วนโหมดดึงเป็นรอบของ Twelve Data ดึงทุก 3 นาทีอยู่แล้ว เกณฑ์จึงเป็น **2.5 เท่าของรอบดึง**
ถ้าใช้เกณฑ์เดียวกันจะฟ้องผิดทุกครั้งที่รอรอบถัดไป แล้วผู้ใช้จะเลิกเชื่อคำเตือนภายในวันเดียว

ตรวจอาการเองได้: เปิดคอนโซลเบราว์เซอร์แล้วพิมพ์ `__gsl.feed.freshness()`

## ระบบแจ้งเตือน

- **เสียง** — โทนไล่ขึ้น = ซื้อ, ไล่ลง = ขาย (สร้างด้วย Web Audio ไม่ต้องมีไฟล์เสียง)
- **แจ้งเตือนหน้าจอ** — เด้งแม้สลับแท็บไปทำอย่างอื่น (กดปุ่มขออนุญาตก่อน)
- **อ่านออกเสียงภาษาไทย** — เปิด/ปิดได้
- **Discord webhook** — ส่งสัญญาณพร้อมแผนเทรดเข้าห้องแชท
- **กฎเตือนส่วนตัว** — ราคาทะลุ/หลุดระดับที่กำหนด, RSI เกิน/ต่ำกว่าค่าที่ตั้ง
- **กันเตือนรัว** — สัญญาณทิศเดิมต้องเว้นระยะตามที่ตั้งไว้ (ค่าเริ่มต้น 5 นาที)
- **ยืนยันเมื่อแท่งปิด** (เปิดไว้เป็นค่าเริ่มต้น) — กันสัญญาณที่กลับไปกลับมาระหว่างแท่งยังไม่ปิด

ตั้งค่าทั้งหมดถูกบันทึกใน localStorage ของเบราว์เซอร์ ไม่มีการส่งข้อมูลออกไปไหน
(ยกเว้น webhook ที่คุณใส่เอง)

## ข้อจำกัดที่ต้องรู้ก่อนใช้เงินจริง

- Backtest ใช้ข้อมูลระดับแท่งเทียน ไม่ใช่ tick — แม่นน้อยกว่าการเทรดจริงเสมอ
- ไม่ได้รวมค่า swap ข้ามคืน ค่าคอมมิชชัน และการที่สเปรดถ่างตอนข่าว
- ข้อมูลที่โหลดได้สูงสุด 1,000 แท่ง → จำนวนไม้ในสถิติมักอยู่หลักสิบ ซึ่ง **ยังน้อย**
  ดูช่วงความเชื่อมั่นประกอบเสมอ อย่าดูแค่ตัวเลขอัตราชนะ
- ตลาดเปลี่ยน regime ได้ อดีตไม่รับประกันอนาคต
- ถ้าต่อข้อมูลจริงไม่ได้ ระบบจะสลับไปโหมดจำลองอัตโนมัติพร้อมแจ้งสาเหตุ
  **ให้ดูมุมซ้ายบนทุกครั้ง** ถ้าขึ้นว่า "ข้อมูลจำลอง" แปลว่ายังไม่ได้ราคาจริง
- ปริมาณซื้อขายของแท่งที่ยังไม่ปิดเป็น **ค่าประมาณการ** (เทียบบัญญัติไตรยางศ์จากเวลาที่ผ่านไป)
  เพราะแท่งที่เพิ่งเปิดยังสะสมปริมาณไม่ครบ ตัวเลขช่วงต้นแท่งจึงแกว่งกว่าปกติ
- ราคาทองไทยที่แสดงเป็นค่าคำนวณจาก XAU/USD × 96.5% × 15.244 กรัม × อัตรา USD/THB ที่ตั้งไว้
  ไม่ใช่ราคาประกาศของสมาคมค้าทองคำ (ไม่รวมค่ากันเหนียว/ส่วนต่างผู้ค้า)

**เครื่องมือนี้ทำเพื่อการศึกษาและช่วยจัดระเบียบการตัดสินใจ ไม่ใช่คำแนะนำการลงทุน
การเทรดทองคำมีเลเวอเรจสูงและขาดทุนเกินเงินต้นได้ ผู้ใช้รับความเสี่ยงเองทั้งหมด**
